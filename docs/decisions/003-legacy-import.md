# 003：旧系统余额结转与历史保留

状态：已采用并正式导入。日期：2026-10-02。

StudyHub 的报名余额可直接修改，初始课时不生成流水，历史也没有付费/赠送拆分和操作人。因此不能把历史增减重放为新系统充值、消课，也不能据差额伪造充值。

采用每条旧报名对应一个课时包。迁移时的剩余课时写为不可变的 legacy_openings，由数据库触发器只对空包初始化一次。后续余额满足：迁移期初 + 新系统流水变动 = 当前余额。期初不能通过普通冲正接口撤销。按当前建议口径，旧余额放入付费余额，赠送为零，界面明确原构成未知；这是迁移口径，不是付款凭证。

legacy_history 单独保存旧增减、零课时记录、当时课程名称、原创建时间、使用日期及删除标记；不改变余额，不推断原操作人，不映射到现课程，不参与新账本冲正。原日期字符串原样保留，不擅自转换时区。API、课时包页和流水页提供只读查询入口。

用户已选择新建「一尘书画院」机构。旧测试机构不混入；被删除的学员及其课时包归档保留。找不到学员的报名与关联历史保留在本地待核对清单，不创建虚构学员，不删除源证据。完整导出包不受筛选影响。

导入工具仅执行本地 SQLite 试导入，不含远程写入能力。稳定的来源编号确保重复执行不重复加课时；导入批次绑定快照摘要，已导入来源遇到不同快照时拒绝覆盖。正式切换需要暂停旧记账、重新导出、重跑对账，并在用户确认后另行执行。禁止清空现有机构或自动挪动管理员身份。

正式部署顺序：先备份新库并应用 0004，再部署支持历史查询的后端和前端，最后导入审核通过的数据。新机构管理员通过现有邀请码流程加入；已绑定其他机构的账号不能自动跨机构。

管理员转移保留历史 actor：旧用户行仍归属原机构并停用，其 openid 改为不可由微信登录产生的退役标记；同一真实 openid 转到新机构的新用户行，原会话撤销。0005 的不可变 admin_transfers 记录前后身份关系。原机构流水和邀请的操作人引用保持不变。正式执行前，已在整库备份恢复的本地 D1 中验证同微信重新登录的新归属及旧会话失效。

正式导入使用 Wrangler 的文件导入通道；本地安装版本 4.144.0 的 executeRemotely 实现明确标注失败恢复原状态。整个文件含前置状态校验、全部业务写入、指定管理员转移和结果约束，不通过逐条远程 query 重放。最终线上导出与计划逐字段核对通过。

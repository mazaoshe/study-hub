# 004：退学退费后的课时结清

状态：已采用。日期：2026-10-04。

用户确认退学即退费，剩余课时须清零。小程序不执行退款支付，也不从课时推算金额；管理员在线下完成退款后确认，金额及方式可写入说明。普通归档仍保留课时，与退学结清分开。

结清使用独立、只追加的 student_withdrawals / withdrawal_lines，避免重建现有不可变 lesson_records 表及其约束。对外课时流水和 CSV 通过 lesson_activity 合并显示 WITHDRAWAL「退学结清」。没有课时包时也展示一条零课时结清事件，保留管理员、时间和说明。

一条结清 INSERT 及数据库触发器原子地核对预览、记录各包负向余额变动、清零并归档所有未结清课时包（包括已归档包），最后归档学员。任一包付费余额为负则整体拒绝，不能通过退学自动豁免透支。

预览展示完整未结清包列表，提交时仅回传学员的状态版本和课时包集合余额版本；新增、删除或变更任一包余额／状态均递增集合版本。固定大小的版本快照避免课时包多时超过请求长度限制。任何中途课时变动、包新增、状态往返均须重新核对；余额先变再还原也不能复用旧预览。普通资料更新未指定状态时不覆盖当前状态；显式状态操作按读取到的版本校验。

机构内 request_id 唯一且校验完整请求摘要。小程序在发送前持久保存预览和请求；断网、响应丢失、页面重开均复用原编号与内容。仅明确表示事务拒绝的错误才丢弃待确认请求，重新读取余额并确认；不将超时当作未提交。

已结清包永久归档：禁止恢复、余额变动、新流水和历史冲正，否则会重新产生已退费课时。学员可恢复后新建课时包继续报名。结清错误不通过普通冲正按钮修改，需要人工核对后设计有审计的纠错流程；当前不提供快捷撤销。

独立审查发现的问题均采纳修复：资料编辑误恢复状态、余额 ABA 并发漏检、空包退学没有可见流水，以及完整包列表快照过长导致请求被拒绝；改用固定大小的双版本快照，并将超长请求视为明确未执行。没有调用外部模型 CLI。集成测试覆盖回滚、并发、幂等、机构隔离、历史与导出、再次报名及前端丢失响应恢复。

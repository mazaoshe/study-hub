```sh
python3 scripts/studyhub_trial.py \
  --snapshot backups/studyhub-20261002-131606 \
  --output backups/studyhub-trial-20261002 \
  --source-org 1 --target-name '一尘书画院'

```

在临时 Workers/D1 运行时验证整批真实数据（仍不连接线上）：

```sh

  ../backups/studyhub-trial-20261002/plan.json \
```

## 正式切换流程（本次已执行）

1. 用户确认试导入范围、隔离的无主数据和课时拆分口径，并暂停旧系统记账。
2. 重新导出最新一致性快照；基于最终快照在新的输出目录试导入，对比这次的数量和余额差异。
3. 导出/备份当前 D1，检查「一尘书画院」尚未由其他操作创建，确定管理员加入方式；现有管理员账号最多绑定一个机构，不能自动挪动。
4. 先应用 0004、0005，再部署后端。scripts/studyhub_cutover.py 从计划和迁移前备份生成带前置约束的 SQL，并在备份恢复的 SQLite 中证明旧业务数据不变；worker/scripts/verify-studyhub-cutover.mjs 在临时 D1 中验证同微信重新登录及精确导入文件。正式执行采用 wrangler d1 execute --remote --file 的文件导入通道（失败恢复原状态），不按独立 query 循环执行，不把本地 SQLite 整库覆盖 D1。小程序源码更新且页面 WXML 编译通过；手机使用新的历史入口需加载新版预览或发布版本。
5. 导入审核后的计划，导出迁移后的线上数据库，与计划逐字段比对并核对原机构数据不变。本次按用户选择转移原记账管理员，撤销其旧会话；该微信账号重新登录即可进入新机构，仍需用户实际手机验收。

## 回滚与重复执行

本地导入使用一个事务，任意失败会完整回滚。相同快照重跑不修改任何数据，即使导入后已有新充值或消课；同一来源的不同快照禁止覆盖。期初和旧历史在数据库层不可修改、删除。正式环境不要用删旧历史、关闭外键或修改流水的方式撤回迁移；启用新业务前可从确认的整库备份恢复，启用新业务后需要单独的保留新流水方案。

# 陌生部署者完整教程

本文面向第一次接手本项目的人，目标是：用自己的微信小程序、Cloudflare Worker 和 D1 部署一套可用的课时工具，并完成第一批业务验收。

所有 `<...>` 都是占位符。请替换为自己的值，不要复制维护者的 AppID、域名、账号、机构名称、数据库 ID 或 Secret。

## 一、先理解角色和数据

系统有两种业务角色：

- **超级管理员**：只管理机构，创建、改名、停用／启用机构并生成该机构的首个邀请码；不直接管理机构内课程和学员。
- **机构管理员**：加入一个机构后，管理本机构的管理员、课程、学员、课时包和课时流水。管理员不能看到或操作其他机构的数据。

数据关系如下：一个学员可以有多个课时包，一个课时包可以共享多门课程；余额属于课时包而不是某一门课程。正常课时包的余额会汇总显示在首页和学员列表。

普通归档与退学结清不同：普通归档保留余额和流水，便于恢复；退学结清表示线下已退费，所有未结清课时包清零并永久锁定，之后重新报名要新建课时包。

## 二、安装和本地确认

### 2.1 安装依赖

环境：Node.js（建议当前 LTS）、npm、微信开发者工具；生产部署还需要 Cloudflare 和微信公众平台权限。

```sh
npm install
npm run check
npm test
npm run build
```

### 2.2 启动本地 Worker

```sh
npm run db:local
npm run dev
```

Worker 默认监听 `http://127.0.0.1:8787`。复制 `worker/.dev.vars.example` 为 `worker/.dev.vars`，填写自己的开发用 AppID、AppSecret 和至少 32 字符的 SESSION_SECRET；`.dev.vars` 不得提交。

在 `miniprogram/config.js` 临时填写本地 API 地址，并用微信开发者工具导入仓库根目录。开发者工具本地设置可以关闭合法域名校验。真机或生产环境不能依赖该开关，必须使用 HTTPS 并配置 request 合法域名。

完整的生产配置、D1 迁移和发布命令见 [部署与微信配置](deployment.md)。

## 三、生产部署和微信配置

按以下顺序操作：

1. 在微信公众平台创建或准备自己的小程序，记下 AppID 和 AppSecret。
2. 在根目录 `project.config.json`、`miniprogram/project.config.json` 和生产 `worker/wrangler.jsonc` 中使用同一个 AppID。AppSecret 不写入这些文件。
3. 在 Cloudflare 创建自己的 D1 数据库，复制 `worker/wrangler.example.jsonc` 为本地未提交的 `worker/wrangler.jsonc`，填写数据库名称、ID、自己的 Custom Domain 和 `APP_ENV=production`。
4. 在 `worker/` 使用 `npx wrangler secret put` 设置 `WECHAT_APP_SECRET` 和 `SESSION_SECRET`。
5. 执行 `npx wrangler d1 migrations apply DB --remote --config wrangler.jsonc`，再执行 `npm run deploy`。
6. 在 `miniprogram/config.js` 配置自己的 Worker HTTPS 地址，在微信后台把它加入 request 合法域名。
7. 用开发者工具重新编译并预览，确认 `/health` 可访问、生产 `/test` 返回 404。
8. 完成下一节的首次登录和超级管理员配置。

部署脚本会校验 AppID 和登录 Secret。不要用 `worker/wrangler.example.jsonc` 直接发布生产，也不要把生产 `wrangler.jsonc`、Secret 或真实数据提交到仓库。

## 四、首次登录与设置超级管理员

### 4.1 设置第一位超级管理员

1. 用准备作为平台负责人的微信账号打开小程序，点击「微信登录」。
2. 如果后端还没有 `SUPER_ADMIN_OPENID`，登录后会看到「加入机构」页；这是已认证但尚未绑定业务角色的状态。
3. 点击「复制账号标识」，在 `worker/` 执行：

   ```sh
   npx wrangler secret put SUPER_ADMIN_OPENID --config wrangler.jsonc
   ```

   粘贴刚才复制的值。它是本小程序登录得到的 openid，不是 AppID、微信号、手机号或开发者工具用户名。
4. 重新登录。成功后首页应进入「机构管理」，可以创建机构。

如果仍停留在加入机构页，确认 Secret 已写入当前 Worker、域名指向当前部署，并退出登录后再次点「微信登录」。不要把 openid 写进前端或文档。

### 4.2 超级管理员管理机构

在「机构管理」页面：

1. 输入机构名称，点击「创建机构」。名称为 1～80 字。
2. 对机构点击「改名称」可修改名称。
3. 对正常机构点击「邀请管理员」，复制显示的一次性邀请码交给首位机构管理员。邀请码有效期 7 天，每个邀请码只能被一个账号兑换。
4. 机构停用后，其管理员下一次请求会被拒绝；需要恢复时点击「启用」。停用不会删除课程、学员、余额和流水。
5. 机构被停用后不能继续发出有效业务操作；重新启用后管理员可重新登录使用。

## 五、机构管理员加入和邀请其他管理员

### 5.1 首位管理员加入

1. 用另一微信账号打开小程序并点击「微信登录」。
2. 在「加入机构」页输入超级管理员提供的邀请码，点击「加入机构」。输入时可带空格、大小写或分隔连字符，服务端会规范化；邀请码本身仍需在有效期内。
3. 成功后进入「首页」。关闭并重新打开小程序，仍应进入该机构首页。

一个微信账号最多绑定一个机构；已绑定业务角色的账号不能兑换另一个机构的邀请码。

### 5.2 邀请第二位管理员

机构管理员进入「管理」→「管理员」→「邀请管理员」，复制邀请码发给对方。对方按上面的加入流程操作。邀请码只显示在创建成功的页面，建议立即复制；有效期 7 天且只能使用一次。再次生成不会自动撤销之前仍有效的邀请码。

「管理」页面会显示本机构管理员数量和状态，但不会显示其他管理员的 openid。

## 六、日常业务操作

### 6.1 课程

进入「管理」→「课程管理」：

1. 点击「新增课程」，填写课程名称和可选备注，点击「保存」。名称最多 80 字，备注最多 500 字。
2. 可搜索课程，点击「编辑」修改名称或备注。
3. 暂停开设某课程时点击「归档」；归档课程仍保留历史记录，但不能用于新的消课。需要继续使用时点击「恢复」。
4. 创建或编辑课时包时只能选择本机构的正常课程。

首次使用建议先创建至少一门课程，再创建学员和课时包。

### 6.2 学员

底部「学员」页是完整名单，不同于首页的待跟进名单：

1. 点击「新增学员」，填写姓名、可选联系电话和备注，点击「保存」。姓名最多 80 字，电话最多 40 字，备注最多 500 字。
2. 用姓名或手机号搜索；可在「正常学员」和「已归档」之间切换。排序可选姓名、剩余课时或最近新增。
3. 学员卡片上的余额只统计正常课时包，显示付费、赠送和总余额。无正常课时包时显示提示。
4. 「更多」→「编辑资料」可以修改资料；「归档」只会停止新的充值、消课和正常操作，余额及历史仍保留。
5. 归档学员在「已归档」中查看，确认后可「恢复」。恢复不会删除历史，也不会改变原有课时余额。

首页只显示正常学员中正常课时包总余额不超过 3 课时的待跟进名单；搜索首页时会查找本机构全部正常学员，包括课时充足或尚未建包的学员。

### 6.3 创建课时包

在学员卡片点击「查看课时包与记录」，或新增学员保存后进入学员详情：

1. 点击「新增课时包」。
2. 勾选一门或多门正常课程；同一个课时包的余额由这些课程共享。
3. 点击「创建」。系统根据课程自动生成课时包名称；进入课时包后也可编辑名称和课程关系。
4. 课时包详情显示付费余额、赠送余额、共享课程和流水。一个学员可以有多个正常课时包。
5. 课时包可单独「归档」或「恢复」。归档包只能查看余额和历史，不能充值或消课；普通归档不清零。

如果新建课时包时没有课程，先返回「管理」→「课程管理」新增课程，再回到学员详情。

### 6.4 充值

充值入口在首页或学员／课时包详情：

1. 对正常学员点击「充值」；多个正常课时包时先选择目标包。
2. 填写「付费课时」和「赠送课时」，未填写的按 0 处理；两项都必须是非负整数，合计必须大于 0。可写备注。
3. 点击「确认充值」，核对学员、课时包和充值后余额，再确认提交。
4. 成功后余额和流水立即刷新；付费与赠送余额分开显示。

充值不会自动抵扣历史消课。若付费余额此前已经透支，充值后可能仍是负数；赠送余额不会变成负数。

### 6.5 消课

消课入口在首页待跟进／搜索结果、学员列表或课时包详情：

1. 选择正常课时包和正常课程。课时包只有一门正常课程时会直接显示该课程；已归档课程不能选择。
2. 填写正整数课时，默认 1，可直接选择 1、2、3；可写备注。
3. 点击「确认消课」，核对课程、扣除课时和预计剩余，再确认提交。
4. 系统优先扣赠送余额，不足部分扣付费余额，因此付费余额允许透支；页面会在确认时提示预计负数。
5. 提交成功后首页／学员列表会刷新余额。网络超时或响应丢失时，应在原页面重试，不要手工重复创建另一笔操作。

学员、课时包或课程归档后不能新增消课；已有流水仍可在满足条件时冲正。

### 6.6 冲正充值或消课

在课时包详情的「课时流水」中找到要纠正的充值或消课：

1. 点击该流水旁的「冲正」。已冲正、已结清或冲正流水不能再次冲正。
2. 先确认要撤销的流水，再填写必填的冲正原因。
3. 提交后系统新增一条相反变动，原流水保留并标记「已冲正」。不要把冲正理解为删除历史。

每笔充值或消课最多冲正一次；如果冲正充值会使赠送余额变成负数，操作会被拒绝且余额、流水都不改变。退学结清后的流水不可冲正。

### 6.7 普通归档和恢复

- **课程**：课程管理中归档／恢复；归档课程停止新的消课。
- **课时包**：课时包详情中归档／恢复；余额和流水保留，归档后不能充值、消课。
- **学员**：学员列表或首页「更多」中归档／恢复；归档后从正常名单移出，余额和流水保留。

归档不是删除。需要查看历史时，进入「学员」→「已归档」或课时包详情；恢复后才可继续正常使用。已退学结清的课时包不能恢复。

### 6.8 退学结清

仅在确认线下退费已经完成后使用。此功能不会发起实际付款，也不会计算退款金额。

1. 从学员「更多」、学员详情或课时包页进入「办理退学结清」。
2. 仔细核对页面列出的全部未结清课时包，包括已归档课时包；页面会显示各包付费和赠送余额。
3. 如有透支的付费余额，先处理透支，系统不会自动豁免。
4. 可填写退费说明，勾选「我已完成线下退费，确认清空上述剩余课时」。
5. 点击「确认退学并清零」，再次核对具名确认框。
6. 成功后全部未结清课时包的付费和赠送余额清零并归档，学员归档，课时流水中出现「退学结清」。

结清是追加的审计记录，不能通过普通冲正撤销；结清后的课时包不能恢复、充值、消课或冲正。学员若重新报名，恢复学员后新建课时包。若提交时页面提示余额已变化，重新核对预览后再决定，不能沿用旧预览强行提交。断网或响应不明时使用页面提供的同一笔重试，系统不会重复清零。

## 七、导出和历史记录

进入「管理」页的「导出 CSV」：

- **学员**：本机构学员资料，包含已归档学员；
- **课时包**：课时包、余额和绑定课程，包含已归档包；
- **流水**：充值、消课、冲正和退学结清，包含已归档数据；
- **历史记录**：仅在导入旧系统数据时使用，只读展示旧系统记录。

点击类型后等待导出完成，再点击「分享文件」保存或发送。CSV 带 UTF-8 BOM，适合用表格软件打开；导出范围是本机构全部数据，不受当前列表搜索条件影响。

旧系统迁移数据的期初与历史不是新流水，不能用普通充值、消课或冲正修改。需要迁移时阅读 [StudyHub 迁移](studyhub-migration.md) 和对应决策文档。

## 八、首次上线验收

请使用专门的测试机构、课程和学员，不要直接用真实学员做破坏性测试。推荐顺序：

1. 运行 `/health` 检查 API；确认生产 `/test` 为 404。
2. 超级管理员登录，创建测试机构并生成邀请码。
3. 机构管理员兑换邀请码，再邀请第二位管理员；验证邀请码一次性和 7 天有效期规则。
4. 创建两门课程和一名测试学员，创建一个绑定两门课程的共享课时包。
5. 充值付费 20、赠送 3，确认余额显示 20／3；分别对两门课程消课，确认共享余额正确。
6. 消课到付费余额为负，确认页面出现透支提示；冲正该消课，确认原流水保留且余额恢复。
7. 归档课程、课时包和学员，确认不能新增业务；恢复后确认可继续使用。不要对已结清包测试恢复。
8. 导出学员、课时包、流水，点击分享文件，用表格软件检查中文、课程关系、归档数据和流水类型。
9. 用测试学员确认退学结清：先确保没有透支，在线下测试记录中确认退费，再办理结清；确认余额清零、学员和课时包归档、流水出现结清记录。
10. 在不同网络下重复一次登录、充值或消课；超时／响应丢失时确认重试不会重复记账。

更细的页面和手机交互检查见 [验收清单](acceptance.md)。

## 九、故障排查

### 登录和权限

- **登录后要求加入机构**：这是未绑定账号的正常状态。超级管理员应设置 `SUPER_ADMIN_OPENID` 后重新登录；普通管理员应向机构管理员索取未使用邀请码。
- **邀请码无效／已使用／已过期**：重新生成并完整复制；确认机构未停用，且该微信账号没有绑定其他机构。
- **机构管理员突然无权访问**：检查机构是否被超级管理员停用、用户是否被停用，或会话是否过期；重新登录。
- **看不到别的机构数据**：这是机构隔离策略。确认当前账号确实加入了目标机构，不要尝试在客户端传入其他机构 ID。

### 网络、微信和 Worker

- **首页显示网络连接失败**：确认 `miniprogram/config.js` 是当前 HTTPS API；确认微信后台已配置 request 合法域名、证书有效、域名 DNS 指向 Cloudflare。
- **`/health` 正常但微信登录失败**：检查 `WECHAT_APP_ID`、Cloudflare 的 `WECHAT_APP_SECRET` 和小程序所用 AppID 是否一致；不要把 AppSecret 放到前端。
- **生产 `/test` 404**：这是预期结果。生产只保留 `/health` 连通检查，使用真实微信登录验收业务。
- **发布脚本停止**：在 `worker/` 检查生产 `wrangler.jsonc` 是否存在，AppID 是否与根目录一致，`WECHAT_APP_SECRET` 和 `SESSION_SECRET` 是否使用 `secret put` 保存为 `secret_text`。
- **所有会话失效**：通常是 `SESSION_SECRET` 被更换；重新登录即可。不要为了保留旧会话把 Secret 写成普通变量。

### 数据和操作

- **迁移后找不到表**：确认执行了 `npx wrangler d1 migrations apply DB --remote --config wrangler.jsonc`，并且生产配置中的 binding 叫 `DB`、数据库 ID 正确。
- **归档后不能充值／消课**：这是预期行为；恢复学员、课时包和所需课程后再操作。普通归档不会删除余额。
- **冲正被拒绝**：可能已经冲正、流水属于已结清包，或冲正充值会使赠送余额为负；先查看课时流水，不要重复提交。
- **退学结清被拒绝**：可能存在付费透支、预览期间余额变化，或学员已经结清。重新打开页面核对；透支需先处理。
- **导出没有下载弹窗**：小程序会先在本地生成 CSV，再显示「分享文件」按钮；等待导出完成后点击该按钮。若微信版本不支持文件分享，升级微信或从 Worker API 另行导出。

仍无法定位时，记录发生时间、页面、HTTP 状态码和面向用户的错误提示，避免记录 AppSecret、SESSION_SECRET、完整 token 或其他个人数据；再检查 [API 说明](api.md) 与技术决策文档。
